What a theme actually controls

A theme is a set of named values, not a stylesheet. Every component reads the names, so switching a theme changes everything at once and nothing needs rewriting.

Every theme ships light and dark

Not an inversion — a second designed palette. Toggle Dark above and watch Vintage Paper: the cream becomes warm brown rather than grey, because the theme defines both.

iOS and small screens

Every app must work on a phone. Press iPad and iPhone above: the navigation collapses, the copilot moves below the content instead of beside it, and the KPI row reflows to two columns. Same components, same theme, different arrangement.

  • The copilot is a panel on desktop and a sheet on phone. A 250px column on a 390px screen is unusable.
  • Tap targets are 44px minimum — Apple's floor, and the reason phone layouts are not just narrow desktop ones.
  • Safe areas matter. Notch and home indicator eat real estate; anything pinned to an edge needs env(safe-area-inset-*).

Decisions this needs

  • Curated, not open. Forty-two is a catalogue, not a product. Each app should offer perhaps four, chosen to suit it. Obra Pía is not a Doom 64 kind of application.
  • Brand vs theme. If an investor picks Cyberpunk for the Obra Pía portal, is that still Obra Pía? Either brand colours override the theme, or theming is limited to a family that keeps the brand intact. Recommendation: the second — offer a small family that reads as the same product.
  • Whose choice is stored. Per-user, per-organisation, or set by an admin? Different answers, different data model.
Nothing here is built yet. This page exists so the shape can be judged before code is written — and to make the three questions above answerable by looking rather than imagining.
